## The challenge.

The library behind the old site had no tokens. Color was hard-coded, dark mode meant a second copy of every component, and components were filed by page type. The rebuild had to happen without pausing a sprint.

</ProseGroup>

## The approach.

</ProseGroup>

<ProseGroup>

### One color system for light and dark.

Tokens name what you're painting, not where. A component reads the right token on any background, so one button works on light and dark, with no second copy.

</ProseGroup>

<Figure caption="The rule, from the system's documentation: the same elements on light and dark, and the token each one uses">

<ProseGroup>

### Components that carry their own rules.

Each button carries its states, sizes and colors for light and dark. Icon Button's smallest sizes fall under the 44px touch target, so the component marks them desktop-only.

</ProseGroup>
